# X-Plane 12.4.4

Working record. Started 2026-11-10, before the upgrade. Juan Luis wants to move to 12.4.4 and explore its SDK. The 0.4 hand flights were flown on 12.4.3 first, so that they judge the plugin and not the new X-Plane ([SPEC](SPEC.md), *Thermal density that follows zi*).

## Where it stands

Read on 2026-11-10 from [Laminar's release notes](https://www.x-plane.com/kb/x-plane-12-4-4-release-notes/), "The SDK Update". The latest entry is dated 2026-11-10, with *X-Plane SDK 440 – Release Candidate 2* and XLua 2.0.0 RC 2, so 12.4.4 is a release candidate, not a release.

[XPPython3's change log](https://xppython3.readthedocs.io/en/latest/changelog.html) ends at 4.7.1 (2026-07-12), which is what is installed. Its newest SDK is 430 (X-Plane 12.4.0+). It loads new features only where available, so 4.7.1 should run on 12.4.4 as on 12.4.3. **None of SDK 440's new functions can be called from Python until XPPython3 supports SDK 440.**

## What in 12.4.4 touches this plugin

From the notes, against what the plugin uses (`adapter/xpio.py`, `adapter/hud.py`):

| 12.4.4 | Here | To check |
| --- | --- | --- |
| Fixed memory corruption and a possible hang on quit when a plugin's `XPLMLoadObjectAsync` is in progress while other plugins load | Our cloud and marker objects load with `xp.loadObjectAsync` | Load and quit, no hang |
| Fixed a possible crash drawing plugin-placed objects with scenery shadows on | Our clouds and markers are instances | A sky with scenery shadows on |
| Fixed plugin memory growing over a session while Plugin Admin is closed | All plugins | Nothing to do |
| Removed the 250-dataref limit per plugin | We publish fewer | Nothing to do |
| `XPLMDrawString` and friends only work in OpenGL draw callbacks, not Panel Graphics | The HUD draws in a window's OpenGL callback | The HUD draws as before |
| Fixed clouds drawn with lines between them (XPD-17677, XPD-18003) | Juan Luis sees flickering streaks near the horizon in X-Plane's clouds, with or without the plugin ([phase4](phase4.md#next-to-xp12s-clouds-and-at-dusk)) | Whether the streaks are gone |
| Weather: improved temperature fluctuations at altitude; visibility now fades over a band estimated from the temperature/dew point spread; better cloud-type detection | The weather's base comes from the temperature and dew point layers ([phase5](phase5.md)) | The rule against X-Plane's layers at 2500 and 3500 m MSL, and Santiago's real day |
| Web server: better port handling and error messages | The test pilot drives X-Plane through it | Implicit in every check |

## What the new SDK could give, once XPPython3 has it

- **Native Dear ImGui and the Panel Graphics API**, drawing without going through OpenGL. A candidate for the settings that come before the cloud looks, if the menu becomes a window, and for the HUD, which draws through OpenGL today.
- **CEF**, interfaces in HTML, CSS and JavaScript inside X-Plane. A settings page or a briefing of the day, for example.
- **An object attached to the aircraft or the observer.** Nothing here needs it yet.

None of this is needed for the thermals. It waits for XPPython3, and then for the stage it belongs to.

## After the upgrade, by the test pilot

One run each, at most 3 minutes, against the numbers already recorded on 12.4.3:

1. Start: the plugin, the flight logger and SeeYou load with no traceback; the menu's status line; flight loop time (165-194 µs on 12.4.3).
2. Force: 1 m/s of uniform lift against m·g·w/V (98.8 N against 98.4 N on 12.4.3, [SPEC](SPEC.md) 0.3.1).
3. Weather's base: `tools/testpilot/check_weather_base.py`, the three cases (12.4.3: our clouds at 2530 and 3116 m MSL under layers at 2500 and 3500 m; Santiago's real day 961 m above the ground).
4. Clouds with scenery shadows on, and a quit: no crash, no hang.
5. A look by screenshot at our clouds against X-Plane's layer at 3500 m, for the flicker where they meet and the horizon streaks.

Then `CLAUDE.local.md` gets the new version. Hand flights only if one of these changes.

## The upgrade

Done by Juan Luis with X-Plane's installer, since a release candidate comes through its beta option and the installer is a window. It updates the install in place; going back to 12.4.3 is not simple, and the 12.4.3 numbers above are the reference instead of a second install.
